# Project Overview

`aiusage` is a local usage monitoring dashboard for AI coding agents. It aggregates token consumption, usage statistics, and cost estimations by directly reading local log files and databases from various AI agents (like Claude Code, Gemini CLI, Codex, OpenCode, and others). The application stack utilizes a Bun-based backend to parse local logs (using custom parsers and the `ccusage` CLI) and a React 19/Vite frontend (with Tailwind CSS and Recharts) to provide a visually rich dashboard.

# File Summaries

## Configuration & Root Files
- **`./bun.lock`**: The lockfile for the Bun package manager that pins dependency versions.
- **`./components.json`**: Configuration file for `shadcn/ui` (and `@base-ui/react`), dictating component paths and styling preferences.
- **`./.gitignore`**: Specifies untracked files and directories (like `node_modules`, build artifacts) to be ignored by Git.
- **`./index.html`**: The main HTML entry point for the Vite Single Page Application (SPA).
- **`./.oxlintrc.json`**: Linter configuration for `oxlint`, defining rules for React and TypeScript parsing.
- **`./package.json`**: NPM package metadata. Defines project dependencies (React, Recharts, Tailwind) and defines executable scripts like `dev`, `build`, `lint`, and `test`.
- **`./README.md`**: Contains initial setup instructions regarding Vite, React, Oxlint configuration, and React Compiler info.
- **`./TODO.md`**: Tracks project progress, tasks, and historical notes about the dashboard implementation, UI modifications (like the removal of the Projects tab), and responsiveness fixes.
- **`./tsconfig.app.json`**: TypeScript configuration tailored specifically for the client/frontend source code.
- **`./tsconfig.json`**: The root TypeScript configuration that references both the app and node environments.
- **`./tsconfig.node.json`**: TypeScript configuration for node-specific context, like parsing `vite.config.ts`.
- **`./vite.config.ts`**: The Vite bundler configuration. It configures the React and Tailwind plugins, sets up alias resolution, and proxies `/api` requests to the Bun backend server on `localhost:3847`.

## Scripts
- **`./scripts/dev.ts`**: A development script runner. Uses `Bun.spawn` to simultaneously start the Bun backend (`bun --watch server/index.ts`) and the Vite frontend, managing graceful shutdown for both child processes.

## Backend (Server)
- **`./server/CCUSAGE-LICENSE`**: Contains licensing information for the `ccusage` module/dependency.
- **`./server/collector.ts`**: Core logic for locating and scanning the local filesystems (`~/.claude`, `~/.codex`, `~/.gemini`, etc.). It identifies local usage log formats, parses them, and normalizes them into unified `UsageEvent` objects.
- **`./server/engine.test.ts`**: The test suite for backend engine logic (token counting and normalization).
- **`./server/engine.ts`**: Wraps and spawns the `ccusage` CLI in a child process to generate aggregated offline usage reports. Normalizes these reports and maps internal outputs to common usage structures.
- **`./server/index.ts`**: The main Bun HTTP server entry point. Serves API endpoints (`/api/sessions`, `/api/health`, `/api/usage`, `/api/scan`), caches recent local usage, and filters usage by date range.
- **`./server/parsers.ts`**: Contains parsing rules for specific log formats (Claude, Codex, Gemini, OpenCode). Translates varied token metadata (input, output, cache read/write, reasoning) into standard metrics and applies cost estimations.
- **`./server/pricing.json`**: A static JSON map providing cost-per-token constants for various models, serving as a fallback for calculating API-equivalent usage costs when not explicitly logged.

## Frontend Application Code
- **`./src/lib/analytics.ts`**: A library of data processing functions. Handles grouping `UsageEvent` data by agent, model, or session; calculating sums/totals across token metrics; and generating daily timeseries data for Recharts.
- **`./src/lib/types.ts`**: Shared TypeScript definitions (`UsageEvent`, `Source`, `UsageResponse`, `AgentId`) utilized by both the frontend visualization and backend parsing logic.
- **`./src/lib/utils.ts`**: Common utility functions, specifically a `cn` wrapper for conditional Tailwind CSS class merging.
- **`./src/App.css`**: Styles for the main application shell, sidebar layouts, loading states, and layout grids.
- **`./src/App.tsx`**: The main dashboard component. Manages application state (dates, agent selection, dark mode), fetches data from the API, and renders the UI layout, statistic cards, charts, and data tables.
- **`./src/index.css`**: Global CSS file. Configures Tailwind theme variables and CSS custom properties (used heavily for chart coloring and dark mode).
- **`./src/main.tsx`**: The main entry point for React. Mounts the `<App />` component inside the StrictMode wrapper into the DOM.

# Other Details & Architecture Notes

- **Data Privacy & Security**: The dashboard operates entirely locally. It parses usage directly from local configuration folders (e.g. `$HOME/.gemini`, `$HOME/.claude`, `$XDG_DATA_HOME/opencode`). No user data is sent remotely; it's explicitly built to keep telemetry local.
- **Port Handling**: The Bun backend spins up on port `3847`. The Vite server proxies any requests directed to `/api` locally to this Bun server, ensuring no CORS issues during development.
- **Cost Estimation mechanism**: The local logs do not always store explicit usage cost. For those tools, the backend maps the known model names in `server/pricing.json` against the recorded token inputs, outputs, and cache metrics to compute an "API-equivalent" estimated cost.
- **Design Philosophy**: The app targets robust UI/UX with responsive design paradigms, featuring a dark/light mode switch, comprehensive filtering, and CSV export functionality directly off the raw offline session metrics. Built with `shadcn` and `@base-ui/react`.
